# Migrated-loan servicing with recalculation off — repaired acceptance

**Local scoped acceptance passed on October 28, 2026.** The two failures in the
[original API/COB experiment](recalculation-off-servicing-acceptance-oct28.md)
are repaired. This supports leaving standard interest recalculation disabled for
the tested migrated-loan servicing paths. It does not release the scheduler,
authorize production deployment, or certify arbitrary historical reprocessing.
Exact Arissto servicing behavior is not an acceptance requirement.

## Backend changes

`PostDueAccruedInterestCalculator.calculateAndApply` now uses the cumulative
actual-principal calculation for loans with a migration baseline and adds only
interest not already materialized by COB or earlier repayments. It puts that
increment on the marked baseline. Payment-time and COB calculations therefore
share the same amount, instead of independently adding overlapping intervals.
The existing non-baseline calculation remains in place. This is prospective
servicing; it does not repair amounts already misallocated by earlier tests or
implement arbitrary backdated downward corrections.

The migrated-loan selector in `InterestPauseWritePlatformServiceImpl` now avoids
regeneration for eligible Credesal cumulative loans with an initialized migration
baseline. Their future interest is earned by the actual-principal calculator,
which reads pause periods directly. Regeneration was rebuilding the imported
opening row and triggering the historical-schedule guard. Create, update and
future cancellation share this selection. Existing prospective-date,
active-loan, overlap, settled-interest and started-pause restrictions remain.
Other cumulative loans retain their existing schedule behavior.

No schema or API payload change was required. Historical schedules, opening
balances and stored future forecasts are not regenerated by this pause action.
